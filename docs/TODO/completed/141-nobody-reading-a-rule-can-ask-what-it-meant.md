# 141 — Nobody reading a rule can ask what it meant

**Kind:** chore · **Severity:** low · **Size:** medium · **Depends on:**
nothing · **Blocks:** nothing · **GitHub:** none — Chris's call on 2026-08-12:
rewrite the technical documentation in ASD-STE100, as a house style rather than
a one-time pass, and **not** the player-facing pages.

## Where we are

ASD-STE100 Simplified Technical English is a controlled language. The aerospace
industry built it for exactly one reader: somebody who has to act on a written
instruction and cannot ask the author what it meant. Its rules are countable —
a sentence cap, one instruction per sentence, no `-ing` verb forms, a noun
cluster no deeper than three, one word for one concept, no ellipsis.

That reader is the one this repository actually has. `CLAUDE.md`,
`docs/INVARIANTS.md` and `docs/PROCESS.md` are read at the top of a session by
an agent that will not stop to ask; the code then cites them **107 times** by
number (`grep -rniE "invariant [0-9]+" src test tools`) plus 21 references to
`docs/INVARIANTS.md` by path, 21 to `docs/COMBAT-SIM.md`, 10 to
`docs/DAMAGE-PATHS.md`, and 2 each to `PROCESS.md` and `ARCHITECTURE.md`. A rule
that reads two ways has been read two ways.

The four rule docs are small and that is the point — the whole of the
instruction surface is about 2,200 words:

| doc | words | what it is |
| --- | --- | --- |
| `docs/ARCHITECTURE.md` | 1,104 | the map |
| `CLAUDE.md` | 423 | the working rules |
| `docs/INVARIANTS.md` | 389 | 15 numbered rules that must hold |
| `docs/PROCESS.md` | 306 | how an issue becomes landed work |

Six reference docs explain a subsystem each and come to about 13,300 words:
`AI-TRAINING`, `BROWSER-TRIALS`, `COMBAT-SIM`, `DAMAGE-PATHS`, `ELITE-A`,
`JAMESON-TRIALS`.

### What is deliberately not in this item

Four surfaces are technical documentation by one reading and are still excluded.
Each exclusion has a reason, and each is cheap for Chris to overrule.

- **The plan archive and the logs.** 124 files in `docs/TODO/completed`,
  `retired` and `research` (157,000 words), plus `docs/DEVLOG.md` and
  `docs/TRAINING-LOG.md` (32,000 more). These are a **record of what was decided
  and measured**, not an instruction to anybody. Rewriting a record restates
  what somebody already wrote, and `CLAUDE.md` sends a reader into those
  directories only for a specific historical decision.
- **Comments in `src/`.** 17,899 comment lines across 224 files, **174,062
  words** — larger than every `.md` in the repository put together, and the
  prose an agent actually reads most. A mass rewrite of it is not a medium item
  and would touch every file in the project at once. The house style covers it
  the way a house style should: M2 states that new and changed comments follow
  it, so the surface converts as files are edited anyway.
- **`README.md`.** Its first section is Chris's own writing, in the first
  person, and rewriting somebody's own words is falsification rather than
  simplification. The rest of it is the public description of the product, which
  is the player-facing half he excluded.
- **`src/constants/CATALOG.md` by hand.** It carries
  `<!-- Generated by tools/constants.ts. Do not edit by hand. -->`. Its prose is
  the doc comments in `src/constants/*.ts`, so it is edited at the source and
  regenerated — which is M4, not an exclusion, but it is the one file where
  "rewrite the doc" means "edit code and run a generator".

## What to do

### M1 — the four rule docs

`CLAUDE.md`, `docs/INVARIANTS.md`, `docs/PROCESS.md`, `docs/ARCHITECTURE.md`.
About 2,200 words, and the highest value per word in the repository: these are
read at the start of every session by every agent.

They are already close in places. `INVARIANTS.md` is 15 short declaratives, and
several need nothing. The work is the rest: sentences that carry two
instructions joined by "and", the passive where an actor exists, `-ing` forms
used as verbs, and noun stacks four deep.

The unit of work is **one rule, unchanged in meaning, said once**. Nothing is
added and nothing is dropped.

### M2 — write the convention down, and do it second

A `## Prose` section in `CLAUDE.md`: the countable rules, the files they cover,
and — the half that matters more — the list of what they never touch. Code and
identifiers, a quoted error string or command, anything quoted from a person,
the novella, the manual and the in-game screens.

**It is written after M1 on purpose.** M1 is where it becomes clear which rules
bite in this repository and which are noise here, and a convention written
before that is a guess. No gate is built; Chris's call on 2026-08-12 was house
style without one.

### M3 — the six reference docs

About 13,300 words. These explain a subsystem, so they argue as well as
instruct, and the argument is the part to protect: a sentence split badly loses
its "because".

`DAMAGE-PATHS.md` is the careful one and goes last. Its table is asserted
against the code by `test/damage-paths.test.ts`, so the prose around the table
is in scope and no unit, owner or path in the table is.

### M4 — the constants' prose, at its source

374 exported constants. The `Purpose` column of `CATALOG.md` is their doc
comments, so this is an edit to `src/constants/*.ts` followed by
`npm run generate:constants` and `npm run constants:check`.

Worth doing and worth doing last: a constant's rationale is read at the moment
somebody is about to change a number, which is the moment a sentence that reads
two ways costs the most.

## Decisions already made

- **Chris, 2026-08-12, on scope.** Technical documentation; not the
  player-facing pages. The manual, `index.html`, the in-game briefing and the
  novella are out.
- **Chris, 2026-08-12, on standing.** A house style, not a one-time pass, and
  **no gate**. The countable rules could be machine-checked and will not be.
- **This plan doc is not itself in STE, and neither is any other.** A plan
  argues a case and records what was measured; it is not an instruction to
  somebody who cannot ask. The house shape in `docs/PROCESS.md` and the voice
  the whole archive is written in take precedence, which is what STE's own
  precedence rule says should happen.
- **The exclusions above are recorded rather than silent**, because a scope that
  is merely not mentioned reads later as a scope that was missed.

## Open questions

**One, and it is Chris's.** Commit messages and the four active plan docs sit on
the line. They instruct nobody, so the decision above keeps them out — but they
are technical writing that agents read constantly, and a different call is
defensible. Promoting them is a one-line change to M2's file list.

## Watch out for

- **Never renumber an invariant.** `docs/INVARIANTS.md` says it, and 107 comments
  in `src/` and `test/` depend on it. A rule may be split into two sentences; it
  may not be split into two rules, merged with its neighbour, or reordered.
- **`test/damage-paths.test.ts` asserts `DAMAGE-PATHS.md`'s table.** The table is
  an inventory the test checks against the code. Prose changes; cells do not.
- **`CATALOG.md` discards a hand edit.** The next `npm run generate:constants`
  overwrites it from the source comments. M4 goes to the source.
- **A quotation rewritten is falsified.** Several docs quote Chris verbatim, and
  `docs/TODO/139`'s own header is one of them. Quoted command output and error
  strings are the same case.
- **The 20-word cap against a sentence that carries a "because".**
  `ARCHITECTURE.md` and the reference docs explain WHY, and this project's
  documentation is unusually willing to argue. Split the sentence; do not drop
  the clause. A longer answer in short sentences is the correct outcome — the
  cap is per sentence, never per document.
- **"One word, one meaning" is already true here, and cuts the other way.**
  `brain`, `commander`, `face`, `rung`, `gate`, `probe` and `tell` are used
  precisely and consistently. A rewrite that reaches for a synonym to vary the
  prose breaks more than it fixes.
- **Give every rule one home** (`CLAUDE.md`). A pass that "clarifies" by
  restating a rule in a second doc has created the duplicate that rule forbids.

## Verification

Prose, so there is no behaviour to pin and no gate to prove failing. What can be
checked is that nothing was lost, and each of these is a command rather than a
reading:

- **Every invariant survives with its number.** The 15 headings before and
  after, compared as a list; then
  `grep -rniE "invariant [0-9]+" src test tools` and confirm every number cited
  still exists.
- **Every citation still resolves.** `grep -rhoE "docs/[A-Z-]+\.md" src test
  tools` — the same seven files, and any section anchor named in a comment still
  present.
- **`npm run lint`, `npm test`, `npm run constants:check`** — green throughout.
  M4 additionally runs `npm run generate:constants` and leaves
  `constants:check` clean, which is what proves the rewrite reached the source
  rather than the generated file.
- **A rule inventory per doc.** Before each file is touched, list the claims it
  makes. After, the list must be the same length and the same claims. This is
  the only check that catches the real failure mode of an STE pass, which is not
  a bad sentence but a dropped condition.
- **What is NOT claimed.** STE compliance itself is not measured, because no
  checker is built. The claim this item can honestly make is "read against the
  rule table", not "gated".

## What landed, 2026-08-12

All four milestones. The rewrite covers **four rule docs, six reference docs and
all 61 files of `src/constants/`**, and nothing outside the scope above moved.

**M1 — the four rule docs.** `CLAUDE.md`, `docs/INVARIANTS.md`,
`docs/PROCESS.md` and `docs/ARCHITECTURE.md`. All 15 invariants keep their
numbers and their claims; the code's **107 citations by number still resolve**,
and the cited set is 1–13 and 15, exactly as before. The seven doc paths that
`src/`, `test/` and `tools/` name are unchanged, at the same counts.

**M2 — the convention.** A `## Prose` section in `CLAUDE.md`: the countable
rules as a table, the surfaces it covers, and the seven kinds of text it never
touches. The one-line rule in `## Style` is deleted rather than kept in step, so
the convention has one home.

**M3 — the six reference docs.** `JAMESON-TRIALS`, `BROWSER-TRIALS`,
`AI-TRAINING`, `ELITE-A`, `COMBAT-SIM`, then `DAMAGE-PATHS` last. Every table,
every measured number and every quotation is untouched. `DAMAGE-PATHS.md`'s
25-row inventory was not edited at all — only the prose around it — because
`test/damage-paths.test.ts` reads that table.

**M4 — the constants' prose.** All 61 files edited at the source, then
`npm run generate:constants`. The catalogue still reports **374 exports and 54
rule ids**, which is what says the pass changed prose and not rules.

### Four things that came out of it, and none were in the plan

1. **A dated report pins its own text.** `JAMESON-TRIALS.md` opens with "**A
   dated report, left as written.**" Its note exists to say that two figures in
   it are stale. An STE pass makes that sentence false, so the note now says what
   is true: the language follows the house style, and no finding, number or
   quotation moved.
2. **`TACTICS` had no JSDoc, and `constants:check` is diff-scoped.** The gate
   only checks constants the diff touched, so an export that predates the gate
   can sit undocumented until somebody edits its file. M4 edited every file in
   the directory, and this was the one it found.
3. **Two quotations attributed to `CLAUDE.md` are no longer in it.**
   `BROWSER-TRIALS.md` quotes *"prefer a fight a human flew to a bot-flown
   measurement"* and *"a well-optimised pirate is a turret that hangs in space
   and snipes"*, and `COMBAT-SIM.md` quotes "threat is not fun". The commit that
   slimmed the agent context took all three out.
4. **`docs/PROCESS.md` cites a step it no longer has.** It says a plan's
   Verification is "tiered to the change (see step 3)", and the file is only
   "# 1. Plan". Steps 2–4 went with the cycle orchestrator on 2026-08-09.

## Both of those, closed 2026-08-13

Chris's call: remove the stale quotes, and fix up the process.

**The quotes are gone, and each claim stayed.** Four attribution sites across the
two files, not two. A quotation of a rule that no longer exists cannot be
repaired by a rewrite, so each one is now the host document's own statement.
`BROWSER-TRIALS.md` opens with the rule as its own and says so — *"One rule is
the whole reason this file exists, and this file is its home"* — which gives the
rule one home instead of an attribution to a file that lost it. The turret
warning is now "Watch for the known failure". `COMBAT-SIM.md` says "Threat is not
the same thing as fun, and this is the check that catches the difference", and
"the one question the numbers cannot". `docs/DEVLOG.md` and `docs/TRAINING-LOG.md`
name `CLAUDE.md` six more times and are deliberately untouched: they are a record
of what was decided, and `TRAINING-LOG.md`'s entries are appended and never
edited.

**`docs/PROCESS.md` has its four steps back**, written around the loop that
actually runs rather than the cycle orchestrator that was deleted. Step 1 is
unchanged. **Step 2 Implement** owns only what is not already `CLAUDE.md`'s: one
plan doc is one unit of work, one milestone is one commit, and two things belong
in the plan doc rather than in a commit message alone — what the plan did not
have, and a milestone that turns out to be wrong. **Step 3 Verify** is what "see
step 3" was always pointing at: `npm run check` always, and a table of what runs
BEYOND it, tiered to what the change touched. **Step 4 Land** is the four pieces
of bookkeeping that keep the active context small, and they are the ones this
item performed by inference from 140's history.

Two accuracies came out of writing it. `npm run elite-a` is named as a fast
subset that is deliberately NOT in `npm run check`, because `npm test` already
runs its assertions (docs/ELITE-A.md) — the old step 3 said "build + elite-a",
which would have read as a contradiction. And the tier table carries a row for
the case that looks like a prose-only change and is not: **a doc comment in
`src/constants/` is the `Purpose` column of `CATALOG.md`**, so prose alone leaves
the catalogue stale and `constants:check` fails. M4 met that, and the rule now
has a home. Two paragraphs that restated `CLAUDE.md`'s Validation rules were cut
before the file landed, because a pass that "clarifies" by restating a rule
creates the duplicate that rule forbids.

`npm run check` green: 4255 passed, 0 failed.
